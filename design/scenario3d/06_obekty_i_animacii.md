# 06. РЕЕСТРЫ: интерактивные объекты (O##) и Mixamo-анимации (A##)

> Это **закрытые словари** производственного сценария (`03`–`05`). Скрипт ссылается на них
> кодами `[O07]` и `[A46]`. Принцип тот же, что во всём дизайне (v0.1 §1): парсер/режиссёр не
> выдумывает — он маппит на закрытый словарь. Тут этот словарь для 3D-слоя.
>
> Ассеты-источники: **только каталог Meshy (`../13`)** + движковые примитивы + декали.
> Ни одна сцена сценария не требует модели вне каталога — это проверено при написании скрипта.

## ЧАСТЬ 1. ИНТЕРАКТИВНЫЕ ОБЪЕКТЫ (O##)

### 1.1. Правила реестра

1. **Объект = слово.** Каждый интерактивный объект несёт немецкое слово с артиклем. Фокус на
   объекте → слово всплывает; первое взаимодействие → слово падает в Wortschatz-журнал
   (см. `02_nemeckiy_sloy.md`). Так каталог Meshy буквально становится учебником.
2. **Источник ассета** — один из трёх, в порядке предпочтения:
   `E##` (каталог Meshy) → `прим.` (движковый примитив: коробка/цилиндр/плоскость, 0 кредитов)
   → `декаль` (текстура на существующей поверхности, 0 кредитов).
3. **Бумага — одна.** Все документы (формуляр, письмо, листовка, контракт, номерок) — один
   меш-примитив «лист» с разными текстурами. Письма в конверте — второй примитив «конверт».
4. Анимации взаимодействия — только из Части 2 (`A##`).

## ЧАСТЬ 2. АНИМАЦИИ MIXAMO (A##)

### 2.1. Как этим пользоваться (пайплайн)

1. **Где:** mixamo.com (бесплатно, аккаунт Adobe). Один раз скачиваешь набор — он общий для
   ВСЕХ персонажей, потому что скелет один (правило каталога `../13` §6: один авториг Meshy,
   Mixamo-совместимые имена костей, эталон — H13).
2. **Имена клипов в Mixamo плавают** (и поиск нечёткий), поэтому в реестре — **поисковый
   запрос**, а не «точное имя». Открываешь поиск, вводишь запрос, выбираешь по превью клип,
   который читается как в описании. Если ничего похожего — бери fallback из последней колонки.
3. **Настройки скачивания:** Format `FBX Binary`, Skin `Without Skin` (скин уже есть у наших
   мешей), 30 fps, Keyframe Reduction `none`. Для локомоций ставь галку **In Place** — движение
   по миру делает контроллер, не клип.
4. **Конвенция имён файлов:** `a##_snake_name.fbx` → в движке клип регистрируется под `anim_id`
   (см. таблицы). Эти же id живут в контракте `scene_actions` (`../12`): режиссёр-LLM выбирает
   только из этого словаря.
5. **Проверка ретаргета:** каждый новый клип сначала на эталоне H13 → потом выборочно H04
   (Шмидт — самая «нестандартная» фигура). Если плечи/бёдра ломает — правь маппинг костей, а
   не качай другой клип.
6. **Маски:** `upper` = клип играет только на верхней половине тела (можно поверх сидения/ходьбы —
   разговор жестами на ходу); `full` = всё тело. Слоёная схема Three.js `AnimationMixer` +
   `additive`/маска по костям.

### 2.7. Сводка закупки анимаций

- **P0 (Акт I играбелен):** 24 + 12 = 36 клипов ≈ один вечер скачивания и ретаргета.
- **P1 (Акты II–III):** +19 клипов.
- **Итого словарь: ~55 клипов на всю линию**, общих для всех 16 персонажей (один скелет).
- Это и есть словарь `anim` для контракта `scene_actions` (`../12`): офлайн-режиссёр и
  LLM-режиссёр выбирают только из этих id. Эмерджентные действия («бью прохожего», «танцую»,
  «обнимаю его») собираются из тех же клипов — отдельных «сюжетных» анимаций не существует.
