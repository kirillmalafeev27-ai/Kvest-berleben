# ЧАСТЬ 1. СХЕМА ИНТЕНТОВ (LLM-парсер)

## 1.1. Принцип

Парсер работает по **закрытому словарю**: LLM не придумывает действия, а маппит свободный ввод игрока на один из заложенных в коде интентов. Если ввод не маппится — возвращается `impossible`, и рассказчик объясняет это внутри мира («Ты примеряешься перепрыгнуть стойку Бюргерамта, но охранник уже смотрит на тебя»).

## 1.2. Конверт интента (IntentEnvelope)

```json
{
  "raw_input": "говорю чиновнице что жена рожает и мне срочно нужна справка",
  "intents": [
    {
      "verb": "persuade",
      "target": "npc_clerk_buergeramt_01",
      "method": "emotional_appeal",
      "honesty": "lie",
      "tone": "desperate",
      "props": { "claim": "family_emergency", "offers_money": 0 },
      "language_used": "de",
      "confidence": 0.92
    }
  ],
  "meta": {
    "multi_intent": false,
    "out_of_scope": false,
    "needs_clarification": false
  }
}
```

Поля:
- **verb** — глагол из закрытого каталога (см. 1.3). Единственное, что движок исполняет.
- **target** — id сущности из текущей сцены. Парсер получает в контекст список доступных целей и не может выдумать новую.
- **method** — уточнение способа (тоже из словаря, свой набор на каждый verb).
- **honesty** — `truthful | half_truth | lie | omission`. Ключевое поле для оси Честность↔Манипуляция.
- **tone** — `polite | neutral | aggressive | submissive | sarcastic | desperate | charming | cold`.
- **props** — параметры: суммы денег, предметы, конкретное утверждение (claim) из словаря клеймов.
- **language_used** — на каком языке игрок пытается говорить (влияет проверка навыка немецкого).
- **confidence** — уверенность парсера. Ниже 0.6 → рассказчик переспрашивает внутри мира («Кассирша поднимает бровь: "Wie bitte?"»).

## 1.4. Правила парсера (вшиты в системный промпт)

1. Выдавать **только валидный JSON**, только глаголы и цели из переданного списка.
2. Сложный ввод («даю охраннику 20 евро и пока он отвлёкся прохожу внутрь») → `multi_intent: true`, массив из двух интентов, движок исполняет последовательно и может прервать цепочку после провала первого.
3. Невозможное физически/вне рамок мира → `out_of_scope: true` + ближайший возможный интент в `fallback`, если есть.
4. Парсер **не оценивает мораль и не предсказывает исход** — только намерение. Исход решает движок.
5. Реплики игрока «в кавычках» передаются рассказчику дословно (для колорита), но геймплейно работает только распарсенный интент.

## 1.5. Примеры парсинга

| Ввод игрока | Результат |
|---|---|
| «молча кладу на стойку 20 евро и смотрю ему в глаза» | `bribe / money / tone: cold / offers_money: 20` |
| «ору что он фашист и я буду жаловаться» | `threaten / report_to_authority / tone: aggressive` + флаг `insult: true` |
| «помогу бабке донести сумки до квартиры» | `offer_help / labor / target: npc_elderly_neighbor` |
| «взламываю систему терминов через даркнет» | `out_of_scope: true`, fallback: `book_appointment / through_fixer` («Сам ты не хакер. Но Ахмед говорил, что знает человека...») |

# ЧАСТЬ 2. ПОВЕДЕНЧЕСКИЙ ПРОФИЛЬ, НАВЫКИ, РЕПУТАЦИЯ

## 2.1. Пять осей личности (−100 … +100, старт 0)

| Ось | −100 | +100 |
|---|---|---|
| **AGGRO** | кроткий | агрессивный |
| **TRUTH** | патологический манипулятор | кристально честный |
| **ALTRU** | эгоист | альтруист |
| **LAW** | криминал | законопослушный |
| **PRIDE** | покорный | гордый/несгибаемый |

Оси игроку **не показываются числами**. Игрок видит последствия и изредка — текстовые «отражения» (NPC говорит: «О тебе говорят, что ты человек слова»).

## 2.2. Как начисляются дельты

После каждого резолва события LLM-аналитик получает: интент + фактический исход + ставки события — и возвращает дельты:

```json
{ "AGGRO": +3, "TRUTH": -5, "ALTRU": 0, "LAW": -2, "PRIDE": +1, "evidence": "солгал чиновнику ради выгоды, средние ставки" }
```

Правила начисления (вшиты в промпт аналитика и пост-валидируются кодом):
- **Вес = ставки.** Мелочь (соврал про возраст бармену) ±1–2. Средние ставки (обман чиновника) ±3–6. Высокие (предал доверившегося NPC, кража у бедного) ±8–15.
- **Считается выбор, а не успех.** Провалившаяся попытка кражи — всё равно сдвиг LAW в минус.
- **Убывающая отдача.** Однотипное действие подряд даёт затухающую дельту (анти-фарм): k-е повторение за игровой день × 0.5^k.
- **Инерция.** Чем дальше ось от нуля, тем дороже её сдвинуть обратно (исправление репутации — долгий путь, и это намеренно).
- **Контекст смягчает.** Кража еды при голоде < кража ради наживы. Аналитик получает состояние игрока (голод, угроза депортации) и учитывает его.
- Код **клампит** дельты аналитика в допустимые диапазоны — LLM не может выдать +50.

## 2.3. Навыки (0–100, растут от практики)

| Навык | Растёт от | На что влияет |
|---|---|---|
| **Deutsch** | любое взаимодействие на немецком (успех ×2, провал ×1) | доступность опций диалога, цены, отношение чиновников |
| **Торг** | haggle, удачные сделки | цены, зарплата по-чёрному |
| **Убеждение** | persuade с honesty: truthful | шансы в честных переговорах |
| **Обман** | deceive/lie, *не пойманный* | шансы лжи; при поимке навык НЕ растёт, но растёт «Хладнокровие» |
| **Хладнокровие** | стрессовые ситуации, провалы без паники | штрафы от стресса, поведение при проверках |
| **Улица** | fare_dodge, hide, flee, ночные районы | избегание опасностей, чтение людей |
| **Бюрократия** | apply, submit_docs, чтение писем | скорость процедур, поиск лазеек |
| **Труд** | work | заработок за смену, доступ к лучшим работам |

Рост: `Δ = base × difficulty × (1 − skill/softcap)`. Softcap 70 — дальше только редкие события-наставники.

## 2.4. Репутация: социальный граф

NPC объединены во **фракции** со своей внутренней молвой:

- Турецкая община (Зонненаллее)
- Арабская община
- Русскоязычная община
- Чиновники (Bürgeramt / Ausländerbehörde — общая база заметок!)
- Работодатели по-чёрному
- Криминальный контур
- Соседи по дому/хостелу
- Волонтёры и соцработники

Механика молвы:
- Каждое значимое событие создаёт **слух** с тегами (`помог`, `обманул`, `не вернул долг`, `надёжный работник`).
- Слух распространяется по графу с вероятностью = близость связей × яркость события; по пути **искажается** (помог донести сумки → «он у фрау Шмидт чуть ли не сын родной»).
- У каждого NPC: личная память о встречах (вес ×3) + фракционная молва (вес ×1).
- Чиновники не сплетничают — они **пишут заметки в дело**. Пойманное враньё в Бюргерамте всплывёт в Ausländerbehörde через неделю.

## 2.5. Как профиль открывает/закрывает контент

Примеры порогов (контентные модули проверяют их в условиях входа):

- `LAW < −30 и Улица > 25` → криминальный контакт сам находит игрока с предложением.
- `ALTRU > 30 и слух «помогает» в общине` → община скидывается на адвоката, когда у игрока беда.
- `TRUTH < −40` → честные опции у части NPC исчезают: тебе просто больше не верят, даже когда говоришь правду (волк и пастух).
- `PRIDE > 40 и AGGRO > 20` → уважение на стройке, но конфликт с бригадиром неизбежен.
- `Deutsch > 50` → открывается весь слой «немецких» NPC и официальных путей.

## 3.1. Герой (дефолтный билд, позже — выбор бэкграунда)

10. **Эмилия** — бариста/студентка, романтическая ветка. Не сюжетная награда, а зеркало: её отношение строго следует профилю игрока.

## 3.5. Пул стартовых событий-модулей (выборка, всего к прототипу ~30)

Формат: `условия входа → ситуация → ветки`

- **«Контролёры в U-Bahn»** — `транспорт без билета` → проверка → заплатить штраф 60 € / убедить / соврать про карту / бежать (Улица-чек) / скандалить. Каждая ветка — свои дельты и слухи.
- **«Кошелёк на тротуаре»** — `случайное, день 3+` → внутри 80 € и айди студента → присвоить / вернуть (квест на полчаса, владелец — внезапно полезный контакт) / сдать в полицию (чек на смелость: ты сам без Anmeldung...).
- **«Богдан не заплатил»** — `3 смены на стройке` → бригадир «забыл» половину → проглотить / потребовать (PRIDE-чек) / угрожать / пожаловаться Виктору (у того свои методы, но будешь должен).
- **«Облава на стройке»** — `5+ смен по-чёрному, вероятность растёт` → Zoll приехал → бежать / прятаться / предъявить «документы Доктора» (страшный чек) / сдаться.
- **«Ужин общины»** — `репутация у Мехмета > 20` → приглашение → социальный эпизод, +связи, открывает комнату в субаренду без Anmeldung.
- **«Эмилия спрашивает прямо»** — `3+ встречи` → «а чем ты вообще тут занимаешься?» → правда / красивая ложь / уход от ответа. Ложь работает... до случайной встречи с ней у стройки.
- **«Срочный термин»** — `Бюрократия > 15 или совет Лены` → лайфхак с отменами терминов в 7 утра → мини-игра настойчивости, честный обход системы.

## 3.6. Долгие арки за пределами недели (наброски)

- **Виза (90 дней):** главный таймер → концовки: контракт и легализация / фиктивный брак / нелегальное подполье / добровольный выезд / депортация.
- **Жильё:** хостел → матрас → WG → своё, каждая ступень требует документов или связей.
- **Язык:** A2 → B1 меняет игру качественно (открывается «немецкий Берлин»).
- **Совесть:** к дню 60 игра сводит игрока с новоприбывшим иммигрантом — и игрок оказывается в позиции Виктора. Что он скажет новичку — финальное зеркало профиля.

# ЧАСТЬ 4. ТЕХНИЧЕСКИЙ КАРКАС

## 4.1. Стек прототипа

- **Клиент:** Three.js (низкополигональный стилизованный Нойкёльн, day/night, болванки-персонажи), UI поверх — обычный HTML (поле ввода, лента повествования).
- **Сервер:** Node.js или Python (FastAPI). Авторитарный: весь стейт и резолвы на сервере.
- **Стейт:** Postgres/SQLite — игрок, NPC-память, граф слухов, флаги событий, календарь.
- **LLM:** 3 роли = 3 промпта:
  - **Parser** — маленькая быстрая модель, строгий JSON, температура ~0.
  - **Narrator** — модель посильнее, темп. ~0.8, пишет 2–5 предложений + реплики NPC; получает резолв и стиль-карточку NPC.
  - **Analyst** — батч-вызов после события (дельты осей) + ежедневная суммаризация «дневника» в память NPC и слухи.

## 4.2. Антигаллюцинационные контракты

1. Narrator получает **результат**, а не право его выбирать: «исход: частичный успех, чиновница отказывает, но записывает на отмену» — и обязан описать ровно это.
2. Narrator не может: давать предметы, называть цены, обещать от лица NPC то, чего нет в стейте. Список «фактов сцены» передаётся явно, всё вне списка — запрещено упоминать как факт.
3. Parser ограничен словарём; неизвестное → `out_of_scope`.
4. Все числовые дельты от Analyst проходят кламп и санити-чеки в коде.
5. Сид рандома резолвов логируется → любой исход воспроизводим для дебага.

## 4.3. Порядок работ

1. **Текстовый прототип** (без 3D): Нойкёльн, 10 NPC, 30 событий, полный цикл Parser→Rules→Narrator→Analyst. Цель — 40 минут интересной сессии.
2. Граф слухов и память NPC: добиться эффекта «мир меня помнит».
3. Балансировка экономики давления (деньги/дни/виза).
4. Three.js-обёртка: один район, перемещение, смена времени суток.
5. Голосовой ввод (Whisper-класс) — опционально, но для иммигрантской темы говорить вслух на ломаном немецком — мощная механика.

## 4.4. Открытые вопросы

- Смерть/провал: депортация = game over или «новая глава в другой стране»?
- Сохранения: позволять ли сейв-скам, который убивает вес выбора? (Склоняюсь к автосейву без откатов.)
- Тон: насколько жёстко показывать тёмные стороны (эксплуатация, расизм)? Нужна планка «честно, но не чернуха».
- Локализация ввода: игрок пишет на родном языке, а `language_used` — отдельное намерение («говорю по-немецки») или авто-детект?
